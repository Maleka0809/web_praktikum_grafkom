Implementasi Challenge & Analisis Konsep

Bagian ini menjabarkan seluruh implementasi Challenge A hingga H secara mendalam, mencakup prinsip teoretis grafika komputer 3D, integrasi kode WebGL/Three.js, bedah kode langkah-demi-langkah, dan analisis visual responsifnya.

Pertanyaan Pemahaman Teori Fundamental Three.js

Apa hubungan Three.js dan WebGL?
Three.js adalah library high-level JavaScript yang mempermudah penggunaan WebGL. Tanpa Three.js, kita harus menulis banyak kode low-level WebGL untuk membuat sekadar objek 3D sederhana.
Mengapa Three.js disebut high-level library?
Karena ia menyembunyikan kompleksitas seperti pembuatan shader, matriks, dan buffer WebGL di balik API berbasis objek yang intuitif (seperti Mesh, Scene, Camera).
Apa komponen minimum agar Mesh dapat terlihat?
Scene, Camera, Renderer, dan Mesh itu sendiri (yang terdiri dari Geometry dan Material). Jika Material merespons cahaya (seperti Lambert/Phong), maka diperlukan Light juga.
Apa itu Geometry, Material, dan Mesh?
Geometry mendefinisikan bentuk/struktur kerangka (vertex). Material mendefinisikan tampilan permukaan (warna, kilap, interaksi cahaya). Mesh adalah gabungan dari Geometry dan Material menjadi objek 3D utuh di dalam Scene.
Apa bedanya MeshBasicMaterial, Lambert, dan Phong?
Basic: Tidak dipengaruhi cahaya sama sekali. Lambert: Dipengaruhi cahaya namun permukaannya kusam/diffuse (tidak ada pantulan kilap). Phong: Merespons cahaya dan memiliki specular highlight (permukaan mengkilap).
Bagaimana cara kerja Shadow (bayangan)?
Agar bayangan muncul: (1) Renderer harus mengaktifkan shadowMap.enabled, (2) Light harus memiliki castShadow = true, (3) Objek pelempar bayangan harus castShadow = true, dan (4) Permukaan penerima (seperti plane/ground) harus receiveShadow = true.
Mengapa aspect ratio dan updateProjectionMatrix penting saat resize?
Jika ukuran window/canvas berubah, rasio lebar-tinggi (aspect ratio) Camera harus disesuaikan dan matriks proyeksinya di-update agar objek tidak terlihat terdistorsi (gepeng/melar).

Analisis Praktikum Abstraction & Performance

  • Abstraction: Three.js menghilangkan kebutuhan menulis boilerplate WebGL manual (setup program, compile shader, bind buffer) sehingga pembuatan scene 3D lebih cepat dan mudah.
  • Performance: Memperbesar resolusi shadow (misal dari 512 ke 2048) atau menambah segmen objek (seperti Sphere) akan meningkatkan kualitas visual secara signifikan, namun juga menambah beban GPU. Menggunakan resolusi optimal yang cukup tajam tapi ringan adalah kuncinya.
  • Transform: Properti seperti position, rotation, dan scale tidak mengubah nilai vertex aslinya secara permanen; melainkan meng-update "Model Matrix" dari objek, yang mana dikalikan dengan vertex asli di dalam GPU di setiap frame (di dalam Vertex Shader).

Challenge A — Tambah Geometry Mesh • Geometry • Transform • Collision Avoidance

1. Konsep Teoretis Grafika Komputer

Dalam grafika 3D, objek direpresentasikan melalui kerangka vertex (simpul) dan face (permukaan) yang disebut Geometry. Untuk merender geometry tersebut agar terlihat di layar, dibutuhkan Material yang menentukan respons permukaan terhadap cahaya dan warna. Penggabungan Geometry dan Material membentuk sebuah Mesh.

Setiap Mesh memiliki Transformasi Spasial yang mencakup Posisi (Translasi), Rotasi, dan Skala, yang dihitung menggunakan Model Matrix untuk menempatkan objek pada koordinat World Space. Menempatkan beberapa objek secara terpisah memastikan mereka tidak menempati titik origin $(0, 0, 0)$ yang sama secara tumpang tindih (Z-fighting).

2. Implementasi Kode

// 1. Inisialisasi Material yang Merespons Cahaya
const standardMaterial = new THREE.MeshPhongMaterial({ color: 0x4df3ff, shininess: 100 });

// 2. Pembuatan Geometry Berbeda
const cylinderGeo = new THREE.CylinderGeometry(0.5, 0.5, 1, 32);
const coneGeo = new THREE.ConeGeometry(0.5, 1, 32);
const torusGeo = new THREE.TorusGeometry(0.4, 0.15, 16, 100);

// 3. Penggabungan ke Mesh dan Pengaturan Posisi (Transform)
const cylinder = new THREE.Mesh(cylinderGeo, standardMaterial);
cylinder.position.set(-2, 0.5, 0); // Translasi ke sumbu X negatif

const cone = new THREE.Mesh(coneGeo, standardMaterial);
cone.position.set(2, 0.5, 0); // Translasi ke sumbu X positif

const torus = new THREE.Mesh(torusGeo, standardMaterial);
torus.position.set(0, 0.5, -2); // Translasi ke sumbu Z negatif
torus.rotation.x = Math.PI / 2; // Rotasi 90 derajat agar merebah

// 4. Penambahan ke Scene Graph
scene.add(cylinder, cone, torus);

3. Bedah Kode Baris per Baris

  • new THREE.MeshPhongMaterial(...): Mengalokasikan shader material yang mampu mengkalkulasi pantulan cahaya spekular dan difus secara dinamis.
  • new THREE.CylinderGeometry(...): Menghasilkan matriks vertex dan index yang mendefinisikan bentuk silinder berdasarkan parameter radius atas, radius bawah, tinggi, dan segmen melingkar.
  • new THREE.Mesh(...): Mengikat data Geometry dengan instruksi shader Material ke dalam satu kesatuan grafis objek 3D.
  • mesh.position.set(x, y, z): Memperbarui komponen translasi dari matriks model objek tersebut, sehingga objek bergeser ke lokasi yang spesifik tanpa menimpa objek lain.

4. Dampak Visual & Hasil Observasi

Ketiga objek (Silinder, Kerucut, Torus) muncul di dalam kanvas pada posisi yang terpisah dengan jarak aman. Bayangan dan kilapan cahaya terlihat secara akurat berdasarkan kelengkungan spesifik masing-masing bentuk geometri.

Challenge B — Material Gallery Shading Models • Light Interaction • Shader Pipelines

1. Konsep Teoretis Grafika Komputer

Model pencahayaan (Shading Models) mendefinisikan kompleksitas matematis bagaimana permukaan memantulkan foton cahaya virtual. Three.js mengabstraksi fragment shader yang rumit menjadi beberapa jenis material siap pakai:

  • MeshBasicMaterial: Hanya me-render Albedo (warna dasar) murni tanpa perhitungan pencahayaan. Ideal untuk flat UI atau objek yang "menyala" sendiri.
  • MeshNormalMaterial: Mengonversi nilai Normal Vector (arah kemiringan 3D, $X,Y,Z$) menjadi rentang warna (R,G,B). Sangat berguna untuk kalibrasi/debugging geometry.
  • MeshLambertMaterial: Mengimplementasikan hukum Lambertian reflectance (Diffuse), menghitung pantulan cahaya kasar/matte berdasarkan dot product sudut antara Normal permukaan dan sinar lampu.
  • MeshPhongMaterial: Menambahkan komponen kilau spekular (Pantulan Blinn-Phong) yang menghasilkan highlight spot tajam layaknya plastik atau logam yang dipoles.

2. Implementasi Kode

const materials = [
  new THREE.MeshBasicMaterial({ color: 0x4df3ff }),
  new THREE.MeshNormalMaterial(),
  new THREE.MeshLambertMaterial({ color: 0x4df3ff }),
  new THREE.MeshPhongMaterial({ color: 0x4df3ff, shininess: 80 })
];

const galleryGroup = new THREE.Group();
materials.forEach((mat, index) => {
  const mesh = new THREE.Mesh(new THREE.SphereGeometry(0.5, 32, 32), mat);
  mesh.position.x = (index - 1.5) * 1.5; // Menyusun berjajar secara dinamis
  galleryGroup.add(mesh);
});
scene.add(galleryGroup);

3. Bedah Kode Baris per Baris

  • new THREE.Group(): Node kosong tanpa wujud visual (objek dummy) yang berfungsi merangkai dan mengelompokkan hierarki anak-anak objek secara kolektif (Scene Graph hierarchy).
  • materials.forEach(...): Iterasi fungsional untuk mengalokasikan objek baru (Sphere) dari satu sumber kelas geometri yang sama, lalu memasangkan tiap material yang berbeda untuk komparasi langsung.
  • mesh.position.x = (index - 1.5) * 1.5: Formula penempatan spasial algoritmik untuk mendistribusikan bola secara seimbang dari titik tengah.

4. Dampak Visual & Hasil Observasi

Jenis Material Karakteristik Tampilan Visual Objek
MeshBasicMaterial Bola tampak bundar datar layaknya piringan 2D murni tanpa ada ilusi bayangan atau perhitungan cahaya.
MeshNormalMaterial Bola memancarkan spektrum pelangi dari $X, Y, Z$ ke dalam nilai RGB secara statis berdasarkan sudut lengkungannya.
MeshLambertMaterial Bola memiliki kedalaman volume 3D dengan shading kusam (matte), kasar seperti tanah liat, murni bereaksi terhadap cahaya tanpa kilau.
MeshPhongMaterial Bola bergradasi halus dengan tambahan bintik kilapan pantulan cahaya (specular highlight) tajam menyerupai plastik/keramik basah.

Challenge C — OrthographicCamera Projection Matrix • View Frustum • Responsive Design

1. Konsep Teoretis Grafika Komputer

Proses mengubah dunia 3D menjadi koordinat piksel 2D pada layar dilakukan dengan Projection Matrix. Terdapat dua paradigma proyeksi:

  • Perspective Projection: Mensimulasikan mata biologis manusia di mana objek jauh terlihat lebih kecil akibat sudut Field of View (FOV), sehingga memberikan efek kedalaman optis sejati (rasa ruang dan jarak).
  • Orthographic Projection: Memproyeksikan sinar sejajar (parallel rays) di mana ukuran objek di layar tetap konstan terlepas dari seberapa jauh objek tersebut dari lensa. Ini umum dipakai untuk game isometrik, rancang bangun (CAD), atau rendering teknis, karena proporsi aslinya dapat diukur presisi.

2. Implementasi Kode

// 1. Inisialisasi Dua Jenis Kamera
const aspect = window.innerWidth / window.innerHeight;
const frustumSize = 5;

const perspectiveCam = new THREE.PerspectiveCamera(50, aspect, 0.1, 100);
const orthographicCam = new THREE.OrthographicCamera(
  frustumSize * aspect / -2, frustumSize * aspect / 2, // Left, Right
  frustumSize / 2, frustumSize / -2,                   // Top, Bottom
  0.1, 100
);

let activeCamera = perspectiveCam;

// 2. Event Listener Perubahan Mode (Tombol P atau Select UI)
document.addEventListener("keydown", (e) => {
  if (e.key.toLowerCase() === "p" || e.key.toLowerCase() === "c") {
    activeCamera = activeCamera === perspectiveCam ? orthographicCam : perspectiveCam;
  }
});

// 3. Handler Resize Jendela Responsif
window.addEventListener("resize", () => {
  const newAspect = window.innerWidth / window.innerHeight;
  renderer.setSize(window.innerWidth, window.innerHeight);
  
  // Update Parameter Perspectif
  perspectiveCam.aspect = newAspect;
  perspectiveCam.updateProjectionMatrix();
  
  // Update Batas Frustum Orthographic
  orthographicCam.left = -frustumSize * newAspect / 2;
  orthographicCam.right = frustumSize * newAspect / 2;
  orthographicCam.updateProjectionMatrix();
});

3. Bedah Kode Baris per Baris

  • new THREE.OrthographicCamera(...): Mendefinisikan matriks kotak frustum absolut. Parameter batas (kiri/kanan/atas/bawah) dikalikan dengan aspect ratio layar demi mencegah distorsi bentuk asimetris saat window tidak berbentuk kubus bujur sangkar.
  • activeCamera = ...: Pointer referensi JavaScript dipindah secara instan di tengah siklus program. Pada iterasi render renderer.render(scene, activeCamera), WebGL otomatis mem-parsing matriks kamera yang kini sedang aktif.
  • updateProjectionMatrix(): Fungsi krusial untuk membilas cache matriks internal GPU. Jika aspek dirubah namun fungsi ini tak dipanggil, kamera akan terus menggunakan kalkulasi geometri lama yang sudah terdistorsi.

4. Dampak Visual & Hasil Observasi

Saat mode kamera diganti, pemandangan seketika beralih. Di mode Perspektif, batas ruang kanvas memiliki vanishing point (titik lenyap) menyempit ke tengah. Begitu beralih ke Orthographic, kedalaman ruang menjadi rata (flattened); kubus dan garis paralel grid menjadi murni lurus tanpa konvergensi paralaks.

Challenge D — Light Animation Dynamic Transform • Real-time Rendering • Animation Loop

1. Konsep Teoretis Grafika Komputer

Untuk memicu interaksi dinamis fotorealistik, sumber cahaya harus bergeser dari waktu ke waktu. Modifikasi posisi cahaya ini mengharuskan GPU mengalkulasi ulang nilai pantulan normal-ke-cahaya untuk setiap piksel di kanvas ($1920 \times 1080 = 2 \text{ juta piksel}$ secara pararel dalam waktu <16 milidetik per frame). Lintasan orbit cahaya parametrik dapat diprogram lewat fungsi osilasi melingkar.

2. Implementasi Kode

const dirLight = new THREE.DirectionalLight(0xffffff, 1.2);
dirLight.position.set(2, 3, 2);
dirLight.castShadow = true;
scene.add(dirLight);

// Helper visualisasi untuk memudahkan pelacakan cahaya
const lightHelper = new THREE.DirectionalLightHelper(dirLight, 0.5);
scene.add(lightHelper);

function animate() {
  requestAnimationFrame(animate);
  const elapsedTime = clock.getElapsedTime(); // Waktu mulus berjalan terus

  if (state.isLightOrbiting) {
    // Kurva orbit lingkaran pada bidang X-Z menggunakan fungsi Trigonometri Sin & Cos
    dirLight.position.x = Math.sin(elapsedTime) * 4;
    dirLight.position.z = Math.cos(elapsedTime) * 4;
    lightHelper.update(); // Sinkronkan model bantu dengan sumber aslinya
  }

  renderer.render(scene, activeCamera);
}

3. Bedah Kode Baris per Baris

  • new THREE.DirectionalLight(...): Instansiasi cahaya sejajar (seperti matahari) yang sinar pancarannya diproses sebagai arah vektor tak terhingga di shader (bukan sekadar radiasi sferis titik radius pusat).
  • clock.getElapsedTime(): Menarik nilai detik floating point absolut secara presisi tinggi sejak modul Three.js Clock dikonstruksi. Hal ini mencegah efek gagap (stuttering) jika frame rate melambat.
  • Math.sin(elapsedTime) * 4: Menghasilkan nilai osilasi $[-4, +4]$ pada ekuator lintasan memutar horisontal seiring berjalannya iterasi waktu.

4. Dampak Visual & Hasil Observasi

Arah bayang-bayang di atas alas (ground plane) berputar $360^\circ$ secara berkesinambungan laksana gerakan jam matahari harian yang dipercepat. Visual DirectionalLightHelper berbentuk kotak kawat mengikuti rotasi, selaras presisi dengan proyeksi terminator gelap-terang pada material Lambert/Phong.

Challenge E — Shadow Quality Shadow Mapping • Texture Resolution • Resource Trade-off

1. Konsep Teoretis Grafika Komputer

Teknik yang digunakan standar Three.js untuk membangun bayangan bertajuk Shadow Mapping. Teknik pasca-proses 2-tahapan ini meliputi:

  1. Depth Pass: Kamera sementara diam-diam dirender pada letak lampu mengarah ke pemandangan. Kedalaman letak z-buffer tersimpan sebagai nilai skala abu-abu piksel ke dalam memori tekstur khusus (Shadow Map).
  2. Render Pass: Saat kamera utama mengambil gambar, poligon memeriksa silang posisi 3D-nya sendiri dengan peta di tekstur shadow map. Jika posisi tertutup (nilai lebih dalam), piksel dirender gelap.

Resolusi piksel peta bayangan sangat mendikte tajam/tidaknya batas bayangan. Resolusi minim mengakibatkan pinggiran bayangan tampak berbentuk kotak bergerigi tebal (Aliasing).

2. Implementasi Kode

// Modifikasi Parameter Resolusi Tekstur Internal Light Shadow 
document.querySelector("#shadowSelect").addEventListener("change", (e) => {
  const size = parseInt(e.target.value); // Misal: "512", "1024", "2048"
  dirLight.shadow.mapSize.width = size;
  dirLight.shadow.mapSize.height = size;
  
  // Membersihkan memori VRAM shadow map lama, memicu Three.js membuat Buffer baru
  dirLight.shadow.map.dispose();
  dirLight.shadow.map = null;
});

3. Bedah Kode Baris per Baris

  • dirLight.shadow.mapSize.width = size: Mereset limit lebar & tinggi buffer internal kamera-bayangan yang menampung tekstur. Standar default adalah $512\times512$.
  • dispose(): Karena resolusi tekstur bayangan disimpan langsung di memori video (VRAM), garbage collection Javascript tidak bisa mengakses driver grafis otomatis. Fungsi ini secara agresif melepaskan blok RAM tersebut demi mencegah kebocoran memori (Memory Leak).

4. Dampak Visual & Hasil Observasi

Resolusi Peta Bayangan Kualitas Bayangan & Beban Performa GPU
$512 \times 512$ Garis tepi pinggiran bayangan hancur berkeping kotak-kotak (pixelated aliasing). Kualitas sangat buruk, namun sangat hemat memori (VRAM).
$1024 \times 1024$ Penyetelan optimal standar industri harian. Kotak-kotak aliasing mulai membaur (blur), menciptakan bayangan proporsional yang cukup ringan di-render.
$2048 \times 2048$ (atau lebih) Pinggiran bayangan ultra-tajam, padat layaknya pantulan sejati. Namun, pada komputer kelas bawah beban komputasi Depth Pass akan memakan separuh performa FPS (lag).

Challenge H — Continuous Object Control State Input • Delta Time • Frame-rate Independence

1. Konsep Teoretis Grafika Komputer

Mekanisme Input kedua adalah State-Based (Kontinu Real-time). Sistem mencatat flag Boolean pada map objek state.keys dan terus dipindai per siklus loop rendering. Paling ideal untuk bergeraknya karakter (WASD) secara mulus tanpa input lag.

Metode ini membutuhkan Delta Time (Waktu antar bingkai) agar objek yang berjalan kontinu tidak melesat abnormal (di luar kendali) ketika dijalankan pada monitor frekuensi $144\text{ Hz}$ dibandingkan monitor $60\text{ Hz}$.

2. Implementasi Kode

// 1. Array Status Keyboard State-Based
const keys = { w: false, a: false, s: false, d: false, q: false, e: false };

window.addEventListener("keydown", (e) => {
  if (keys.hasOwnProperty(e.key.toLowerCase())) keys[e.key.toLowerCase()] = true;
});

window.addEventListener("keyup", (e) => {
  if (keys.hasOwnProperty(e.key.toLowerCase())) keys[e.key.toLowerCase()] = false;
});

// 2. Pemrosesan STATE-BASED + DELTA TIME di Loop Render
function animate() {
  requestAnimationFrame(animate);
  const delta = clock.getDelta(); // Mengekstrak sela waktu riil berlalu
  
  if (state.isAnimationPlaying) {
    const moveSpeed = 5.0 * delta; // Skala kecepatan dikalikan delta (Frame-rate Independent)
    const rotSpeed = 3.0 * delta;

    // Translasi (Continuous Movement)
    if (keys.w) mainCube.position.z -= moveSpeed;
    if (keys.s) mainCube.position.z += moveSpeed;
    if (keys.a) mainCube.position.x -= moveSpeed;
    if (keys.d) mainCube.position.x += moveSpeed;
    
    // Rotasi (Continuous Rotation)
    if (keys.q) mainCube.rotation.y += rotSpeed;
    if (keys.e) mainCube.rotation.y -= rotSpeed;
  }
  ...
}

3. Bedah Kode Baris per Baris

  • clock.getDelta(): Menarik selisih waktu detik pecahan persis sesudah bingkai sebelumnya digambar usai. Pada laju FPS 60Hz biasanya bernilai $\approx 0.016$ detik, sedangkan FPS 144Hz bernilai $\approx 0.007$ detik.
  • moveSpeed = 5.0 * delta: Mengimplementasikan hukum gerak linear. Kecepatan dikompensasi secara proporsional, menjamin kubus bergeser senilai murni 5.0 unit WebGL per detik di kehidupan nyata, terbebas dari inkonsistensi rendering perangkat keras.

4. Dampak Visual & Hasil Observasi

Input penekanan tombol WASD merespon tanpa tersendat dan tanpa jeda tunda OS-keyboard. Rotasi putar sumbu vertikal "Q" dan "E" juga berkesinambungan mengalir halus. Kecepatan gerak/putar selalu stabil pada perangkat keras komputer lambat maupun super cepat sekalipun.
