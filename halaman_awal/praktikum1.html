PRAKTIKUM 01

Interactive Canvas

Eksperimen objek 2D, animasi, transformasi, mouse, keyboard, State-Based, dan Event-Based.

SOAL PRAKTIKUM

Penjelasan Logika & Pseudocode

Setiap topik dijelaskan menggunakan bahasa sehari-hari yang sangat mudah dipahami (seperti sedang bercerita) beserta fungsinya, lalu diikuti dengan implementasi kodenya.

HTML Canvas ibarat sebuah selembar kertas kosong digital di halaman web. Kertas ini tidak bisa menggambar dirinya sendiri — kita harus menggunakan JavaScript sebagai "tangan" dan "kuas" untuk mencoret-coret di atasnya.

📦
KONSEP DASAR
Cara Menyiapkan Kertas dan Alat Gambar
Sebelum menggambar, kita butuh dua hal: 1. Kertasnya (Canvas) dan 2. Alat gambarnya (Context). Context 2D ini ibarat kotak pensil ajaib yang berisi kuas, cat warna, dan penggaris. Semua perintah menggambar akan menyuruh alat ini.
📋 Penjelasan Logika & Pseudocode
// TAHAP 1: Menyiapkan Tempat Menggambar di HTML
Kita buat elemen <canvas> dan tentukan ukuran panjang & lebarnya.
Ini seperti memotong kertas sesuai ukuran yang kita mau.

// TAHAP 2: Menghubungkan Kertas ke JavaScript
Kita panggil kertas tadi ke dalam JavaScript menggunakan 'getElementById'.
Tujuannya agar JavaScript tahu kertas mana yang mau digambar.

// TAHAP 3: Mengambil Alat Gambar (Konteks 2D)
Kertas saja tidak cukup, kita butuh alat tulis!
Perintah getContext("2d") ibarat mengambil sekotak alat lukis.
Kita simpan alat lukis ini di variabel bernama 'ctx'.

// TAHAP 4: Mulai Menggambar!
Sekarang kita bisa menyuruh 'ctx' menggambar apa saja:
- ctx.fillRect : "Tolong gambarkan kotak langsung dengan warnanya"
- ctx.arc      : "Tolong buatkan garis melengkung atau lingkaran"
- ctx.lineTo   : "Tolong tarik garis lurus"
- ctx.stroke   : "Tolong tebalkan garis yang barusan saya minta"
💻 Kode HTML + JavaScript (state-based.js)
<!-- Di file HTML: buat elemen canvas -->
<canvas
  id="graphicsCanvas"
  width=960
  height=600>
</canvas>

// Di JavaScript: ambil canvas dan konteks
const stateCanvas =
  document.getElementById("graphicsCanvas");

const stateCtx =
  stateCanvas.getContext("2d");

// Simpan ukuran agar mudah dipakai
const SW = stateCanvas.width;  // = 960
const SH = stateCanvas.height; // = 600
💡 Fungsi getContext("2d") sangat penting karena tanpa ini, kita tidak punya akses ke perintah-perintah seperti menggambar kotak atau lingkaran. Selalu simpan di variabel pendek seperti ctx agar mudah diketik berulang-ulang.
📐
SISTEM KOORDINAT
Cara Komputer Menentukan Posisi (X dan Y)
Di pelajaran matematika sekolah, titik tengah (0,0) biasanya ada di tengah. Di komputer, titik (0,0) selalu ada di pojok KIRI ATAS layar. Semakin ke kanan, nilai X bertambah. Semakin ke BAWAH, nilai Y bertambah. Memahami ini penting agar gambar kita tidak nyasar.
📋 Penjelasan Logika & Pseudocode
Pojok Kiri Atas adalah Titik Nol (0, 0).

→ Jika kita ingin geser ke KANAN, kita tambah nilai X-nya.
↓ Jika kita ingin geser ke BAWAH, kita tambah nilai Y-nya.

Contoh Peta Canvas ukuran 960 x 600:
- (0, 0)       : Pojok kiri atas (Mulai)
- (960, 0)     : Pojok kanan atas
- (0, 600)     : Pojok kiri bawah
- (960, 600)   : Pojok kanan bawah
- (480, 300)   : Tepat di tengah-tengah canvas!

BAGAIMANA JIKA INGIN MENGGAMBAR DI TENGAH?
Kita tinggal membagi lebar canvas dengan 2 (untuk X) 
dan membagi tinggi canvas dengan 2 (untuk Y).
💻 Kode — Contoh Posisi
// Lebar total (960), Tinggi total (600)
const SW = stateCanvas.width;
const SH = stateCanvas.height;

// Gambar nempel di pojok kiri atas
ctx.fillRect(0, 0, 100, 50);

// Menggambar persis di tengah canvas
// SW/2 = 480, SH/2 = 300
// Dikurangi setengah ukuran kotak agar benar-benar di tengah
ctx.fillRect(
  SW/2 - 50,  
  SH/2 - 25,  
  100, 50
);
💡 Fungsi menyimpan canvas.width ke dalam variabel SW adalah agar kita tidak perlu mengingat angka 960 terus-menerus. Jika suatu saat ukuran canvas di HTML diubah, kode JavaScript kita akan otomatis menyesuaikan tanpa perlu diedit ulang!

URUTAN MENGGAMBAR
Aturan Wajib: Celup Cat Dulu, Baru Melukis!
Di dunia nyata, kita harus mencelupkan kuas ke cat warna dulu sebelum menyapukannya ke kertas. Canvas bekerja dengan cara yang sama: Atur warnanya (style) DULU, baru perintah menggambarnya.
📋 Penjelasan Logika & Pseudocode
// ATURAN DASAR MENGGAMBAR

1. Untuk Persegi Panjang (Sangat Mudah):
   Pilih warna cat → Langsung tempelkan bentuk kotaknya!
   (Tidak perlu ribet menggambar garis satu-satu)

2. Untuk Bentuk Lain (Garis, Lingkaran, Segitiga):
   Kita harus membuat "Jalur Sketsa" (Path) terlebih dahulu.

   - SIAPKAN SKETSA BARU (beginPath) : Hapus coretan sebelumnya.
   - PINDAHKAN PENSIL  (moveTo)    : Angkat pensil ke titik awal.
   - TARIK GARIS       (lineTo)    : Geser pensil membentuk jalur.
   - BERI WARNA/TEBALKAN (fill/stroke) : Warnai bagian dalam sketsa 
                                         atau tebalkan garis luarnya.
💻 Kode — Perbandingan (state-based.js)
// Cara 1: Kotak (Langsung)
// Celup ke cat biru, lalu cetak kotak!
stateCtx.fillStyle = "#3b82f6";
stateCtx.fillRect(80, 90, 170, 105);

// Cara 2: Sketsa Garis (Path)
stateCtx.beginPath();       // Kertas sketsa baru!
stateCtx.moveTo(310, 110);  // Taruh pensil di awal
stateCtx.lineTo(500, 185);  // Seret pensil ke tujuan
stateCtx.strokeStyle = "#f43f5e"; // Pilih cat merah
stateCtx.lineWidth   = 4;         // Kuas tebal
stateCtx.stroke();          // Tebalkan garisnya!
💡 Kenapa beginPath() sangat wajib? Jika kita lupa, garis yang kita buat sebelumnya akan ikut tersambung dan diwarnai lagi bersama garis yang baru. Akibatnya gambar kita akan terlihat acak-acakan tersambung satu sama lain.

Primitif adalah bentuk-bentuk dasar pembangun grafis. Ibarat lego, dengan menggabungkan kotak, garis, lingkaran, dan segitiga, kita bisa membuat gambar apapun. Berikut cara Canvas menggambar bentuk-bentuk dasar ini.

▬
BENTUK 1
Kotak (Rectangle) — Paling Cepat dan Mudah
Kotak adalah anak emas di Canvas. Dia punya perintah khusus fillRect yang bisa langsung mencetak kotak solid hanya dalam satu baris perintah tanpa perlu membuat sketsa (path).
📋 Penjelasan Logika & Pseudocode
// BAGAIMANA CARA KERJANYA?
Kita hanya perlu memberitahu komputer 4 hal:
1. Posisi X (Kiri-Kanan)
2. Posisi Y (Atas-Bawah)
3. Berapa lebarnya
4. Berapa tingginya

// ANALOGI SEHARI-HARI
Bayangkan kita punya stempel berbentuk kotak.
Kita arahkan stempel ke koordinat (X=80, Y=90).
Lalu kita tekan stempel yang berukuran lebar 170 dan tinggi 105.
Jadilah sebuah kotak persegi panjang secara instan!
💻 Kode (state-based.js — stateDraw)
// Set warna cat biru
stateCtx.fillStyle = "#3b82f6";

// Stempel kotak langsung: fillRect(X, Y, Lebar, Tinggi)
stateCtx.fillRect(80, 90, 170, 105);

// Kalau hanya mau garis tepinya saja (tanpa isi):
stateCtx.strokeStyle = "#3b82f6";
stateCtx.lineWidth   = 2;
stateCtx.strokeRect(80, 90, 170, 105);
💡 Fungsi fillRect sangat cepat dieksekusi komputer. Oleh karena itu, background game atau elemen kotak dalam game 2D biasanya digambar menggunakan fungsi ini.
╱
BENTUK 2
Garis (Line) — Menyambungkan Titik A ke Titik B
Untuk membuat garis, kita bermain "hubungkan titik-titik". Kita taruh pensil di satu titik, seret ke titik lain, lalu tebalkan dengan spidol.
📋 Penjelasan Logika & Pseudocode
// PROSES MENGGAMBAR GARIS:
1. "Siapkan kertas kosong!" (beginPath)
2. "Angkat pensil, taruh di titik A(310, 110)." (moveTo)
   *Pensil belum menyentuh kertas, jadi tidak ada bekas coretan*
3. "Tekan pensil dan seret lurus ke titik B(500, 185)." (lineTo)
   *Sekarang ada sketsa garis tipis yang belum kelihatan*
4. "Ambil spidol warna merah bata, ukuran 4mm." (strokeStyle & lineWidth)
5. "Tebalkan sketsa tadi pakai spidol!" (stroke)
   *Garis akhirnya muncul di layar*
💻 Kode (state-based.js — stateDraw)
// Siapkan kertas sketsa
stateCtx.beginPath();

// Taruh pensil di titik A
stateCtx.moveTo(310, 110);

// Seret pensil ke titik B
stateCtx.lineTo(500, 185);

// Siapkan spidol merah
stateCtx.strokeStyle = "#f43f5e";
stateCtx.lineWidth   = 4;

// Tebalkan garisnya!
stateCtx.stroke();
💡 Kita bisa memanggil lineTo berulang kali untuk membuat garis zigzag yang panjang sebelum memanggil stroke(). Komputer akan menggambar semuanya sekaligus dengan sangat efisien.
⬤
BENTUK 3
Lingkaran (Circle) — Menggunakan Busur Derajat (Arc)
Komputer menganggap lingkaran sebagai "garis lengkung yang berputar 360 derajat". Kita menggunakan fungsi arc() (busur) dengan menentukan titik tengahnya seperti memegang jangka.
📋 Penjelasan Logika & Pseudocode
// CARA KERJA JANGKA KOMPUTER (arc):
1. Tancapkan jarum jangka di tengah (cx, cy).
2. Lebarkan pensil jangka sepanjang jarak Radius (r).
3. Putar jangka dari sudut Awal sampai sudut Akhir.

// TENTANG SUDUT DI KOMPUTER (RADIAN):
Komputer tidak paham "360 derajat". Komputer menggunakan "Radian".
- Setengah lingkaran = Nilai PI (3.14)
- Satu lingkaran penuh = 2 dikali PI (Math.PI * 2)

// LOGIKA KODE:
"Mulai sketsa baru."
"Tancapkan jangka di (700, 135), rentangkan 58 piksel."
"Putar penuh dari 0 sampai 2*PI."
"Warnai bagian dalamnya dengan warna hijau."
💻 Kode (state-based.js — stateDraw)
// Mulai sketsa
stateCtx.beginPath();

// arc(TengahX, TengahY, Radius, SudutAwal, SudutAkhir)
stateCtx.arc(
  700, 135,       // Titik tengah
  58,              // Jarak radius
  0, Math.PI * 2  // Putar satu putaran penuh
);

// Isi warnanya
stateCtx.fillStyle = "#22c55e";
stateCtx.fill();
💡 Fungsi fill() bertugas seperti tool "Cat Tumpah (Paint Bucket)" di Photoshop. Ia akan mencari area tertutup yang kita buat dari sketsa, lalu mengisi bagian dalamnya dengan warna yang kita pilih.
▲
BENTUK 4
Segitiga — Menutup Jalur (Close Path)
Tidak ada rumus instan pembuat segitiga di Canvas! Kita harus menggunakan teknik menggambar 3 garis yang saling terhubung. Bagian terpentingnya adalah menutup garis terakhir agar segitiganya rapat.
📋 Penjelasan Logika & Pseudocode
// LANGKAH MEMBUAT SEGITIGA:
1. Mulai sketsa baru (beginPath).
2. Taruh pensil di Puncak Segitiga (moveTo).
3. Tarik garis turun ke Kiri Bawah (lineTo).
4. Tarik garis geser ke Kanan Bawah (lineTo).

// LANGKAH KRUSIAL: Menutup bentuk
Saat ini bentuknya masih seperti huruf 'V' terbuka.
Kita bisa saja repot-repot menarik garis lagi ke puncak,
TAPI, ada perintah ajaib bernama closePath()!

Perintah closePath() artinya: "Tarik garis lurus dari titik terakhirmu
kembali langsung ke titik saat kamu pertama menaruh pensil (moveTo)."
Otomatis segitiga akan tertutup rapat!
Setelah rapat, kita tumpahkan cat ke dalamnya (fill).
💻 Kode (state-based.js & event-based.js)
stateCtx.beginPath();

// Taruh pensil di puncak
stateCtx.moveTo(130, 360); 

// Tarik ke kiri bawah
stateCtx.lineTo(65,  490); 

// Tarik ke kanan bawah
stateCtx.lineTo(195, 490); 

// Otomatis tarik garis kembali ke puncak (130, 360)
stateCtx.closePath();

// Tumpahkan cat oranye
stateCtx.fillStyle = "#f97316";
stateCtx.fill();
💡 Teknik closePath() ini adalah rahasia untuk membuat poligon (segi banyak) apa saja. Mulai dari segi lima, segi delapan, atau bentuk bintang sekalipun, kita tinggal menghubungkan titik-titiknya lalu memanggil closePath().

Memberi warna di Canvas tidak sekadar cat padat. Kita bisa menggunakan transparansi, mengganti-ganti warna dengan pola perputaran, dan bahkan memberikan efek cahaya (glow) agar objek terlihat hidup.

🎨
TRANSPARANSI
Warna RGBA — Membuat Efek "Kaca Pudar"
Selain kode Hex (seperti #3b82f6), kita bisa menggunakan RGBA (Red, Green, Blue, Alpha). Bagian yang spesial adalah 'Alpha' — ini menentukan tingkat seberapa "tembus pandang" warnanya.
📋 Penjelasan Logika & Pseudocode
// MEMAHAMI TINGKAT KETEMBUSPANDANGAN (ALPHA)
Nilai Alpha berkisar dari 0.0 sampai 1.0.
- Alpha 1.0 = Cat warna padat (tidak tembus sama sekali).
- Alpha 0.0 = Kaca bening 100% (tidak terlihat sama sekali).
- Alpha 0.5 = Semi-transparan (seperti kacamata hitam).

// KASUS PENGGUNAAN DI PRAKTIKUM: EFEK TRAIL
Alih-alih menghapus seluruh canvas menjadi putih bersih tiap frame,
kita mengecat ulang seluruh canvas dengan warna hitam tapi 
Alpha-nya hanya 0.13 (sangat tipis / tembus pandang).

Apa akibatnya? Gambar bola dari detik sebelumnya tidak langsung hilang, 
tapi tertimpa selapis demi selapis cat hitam tipis. 
Lama-lama gambar lama memudar → Terciptalah efek ekor berbayang (trail)!
💻 Kode (state-based.js — stateDraw)
// Warna padat biasa (Hex)
stateCtx.fillStyle = "#3b82f6";

// Warna hitam kebiruan dengan transparansi 13%
// format: rgba(merah, hijau, biru, alpha)
stateCtx.fillStyle =
  "rgba(7, 17, 31, 0.13)";

// Cat seluruh canvas dengan warna tembus pandang ini
stateCtx.fillRect(0, 0, SW, SH);
💡 Efek transparan rgba adalah trik rahasia di balik animasi yang terasa mulus dan sinematik. Tanpa ini, pergerakan bola di layar akan terlihat sangat kaku dan kering.
🌈
GANTI WARNA
Rotasi Palet Warna dengan Rumus Modulo (%)
Bagaimana cara membuat warna berubah berurutan setiap diklik, lalu kembali lagi ke awal saat warnanya sudah habis? Jawabannya adalah menggunakan "Rak Warna" (Array) dan rumus sisa bagi "Modulo" (%).
📋 Penjelasan Logika & Pseudocode
// PERSIAPAN RAK WARNA:
Kita punya rak (Array) berisi 5 botol warna.
Urutannya: 0(Ungu), 1(Merah), 2(Hijau), 3(Kuning), 4(Biru)
Kita catat nomor botol yang sedang dipakai, misal mulai dari = 0.

// LOGIKA SAAT DIKLIK:
Tiap klik, kita ingin geser ke botol berikutnya (nomor + 1).
Tapi kalau sudah sampai botol nomor 4, kita ingin balik ke 0!

// KEAJAIBAN RUMUS MODULO (SISA BAGI):
(Nomor + 1) dibagi 5, ambil sisanya!
- Klik 1: (0+1) / 5 = Sisa 1 → Pakai Merah
- Klik 2: (1+1) / 5 = Sisa 2 → Pakai Hijau
- Klik 3: (2+1) / 5 = Sisa 3 → Pakai Kuning
- Klik 4: (3+1) / 5 = Sisa 4 → Pakai Biru
- Klik 5: (4+1) / 5 = Tepat habis! Sisa 0 → Balik ke Ungu!

Hasilnya? Warnanya berputar terus tanpa pernah error karena kehabisan botol.
💻 Kode (state-based.js)
// Rak botol warna (Array)
const stateColors = [
  "#8b5cf6", // 0: ungu
  "#f43f5e", // 1: merah
  "#22c55e", // 2: hijau
  "#facc15", // 3: kuning
  "#3b82f6"  // 4: biru
];
let stateColorIndex = 0; // Botol saat ini

stateCanvas.addEventListener("click", () => {
  // Rumus Modulo: Maju 1, balik ke 0 kalau mentok
  stateColorIndex =
    (stateColorIndex + 1) % stateColors.length;
    
  // Pakai warna dari botol yang baru dipilih
  stateBall.color = stateColors[stateColorIndex];
});
💡 Trik Modulo ini sangat sering dipakai dalam pembuatan Game. Contohnya untuk mengganti giliran pemain (Player 1, Player 2, Player 3 → Balik ke Player 1) atau animasi sprite karakter yang berjalan (Frame 1, 2, 3 → Balik 1).
✨
EFEK CAHAYA
Membuat Objek Bersinar (Shadow Glow)
Di Canvas, fitur "bayangan" (shadow) bisa disulap menjadi efek cahaya neon (glow). Caranya adalah dengan membuat warna bayangan tersebut sama persis dengan warna objeknya, lalu memberikan nilai blur (pendaran) yang tinggi.
📋 Penjelasan Logika & Pseudocode
// CARA MENGHIDUPKAN LAMPU NEON:
1. Tentukan seberapa terang pendarannya (shadowBlur).
   Semakin besar angkanya, cahayanya makin menyebar luas.
2. Tentukan warna pendarannya (shadowColor).
   Buat sama dengan warna objek agar terlihat bersinar dari dalam.
3. Gambar objeknya! (Tiba-tiba objeknya bercahaya)

// PERINGATAN KERAS: MATIKAN LAMPU JIKA SUDAH SELESAI!
Kuas Canvas itu sangat pelupa. Jika kamu menyalakan 'shadowBlur', 
kuas akan terus menggambar SEMUA objek selanjutnya dengan efek cahaya!

Oleh karena itu, ada aturan emas:
- Nyalakan shadowBlur = 25
- Gambar Bola (Bola jadi bersinar)
- MATIKAN shadowBlur = 0  <--- WAJIB!
- Gambar kotak Player (Kotak tergambar normal, tidak ikut bersinar)
💻 Kode (state-based.js — stateDraw)
// Siapkan sketsa bola
stateCtx.beginPath();
stateCtx.arc(stateBall.x, stateBall.y, stateBall.r, 0, Math.PI * 2);
stateCtx.fillStyle   = stateBall.color;

// 1. Nyalakan Lampu Neon!
stateCtx.shadowBlur  = 25;          
stateCtx.shadowColor = stateBall.color; 

// 2. Gambar Bolanya
stateCtx.fill();

// 3. MATIKAN LAMPU NEON! (Wajib)
stateCtx.shadowBlur  = 0;           

// Lanjut menggambar objek lain dengan aman...
💡 Efek shadow di Canvas cukup membebani kerja komputer karena butuh perhitungan grafis yang kompleks. Jangan pakai terlalu banyak glow di puluhan objek sekaligus jika tidak ingin animasinya menjadi lag!

Sebuah gambar diam bisa hidup menjadi animasi jika kita menggambarnya berulang-ulang dengan posisi yang sedikit bergeser. Jika kita melakukannya sangat cepat (60 kali per detik), mata kita akan tertipu dan melihatnya sebagai gerakan yang mulus. Inilah yang disebut Game Loop.

🔄
MESIN WAKTU
Jantung Animasi (requestAnimationFrame)
Kita butuh sebuah mesin yang terus berdetak memanggil fungsi gambar kita tiada henti. Di browser web, mesin terbaik untuk ini adalah requestAnimationFrame. Mesin ini super cerdas karena dia sinkron dengan layar monitor kita.
📋 Penjelasan Logika & Pseudocode
// BAGAIMANA MESIN ANIMASI BEKERJA?

Kita buat satu Fungsi Utama (Siklus), isinya 3 langkah baku:
1. HAPUS: "Tolong bersihkan seluruh coretan di kanvas."
2. HITUNG: "Bola tadi di X=100. Sekarang geser ke X=105 ya."
3. GAMBAR: "Sekarang gambar bolanya di posisi X=105 yang baru."

// TRIK SIKLUS TIADA HENTI (REKURSIF)
Di bagian paling akhir dari fungsi tersebut, kita berteriak ke browser:
"Hei Browser, kalau layarmu sudah siap berkedip lagi, 
 tolong panggil fungsi ini dari awal ya!" 
(Inilah peran requestAnimationFrame)

Alur Kejadiannya:
- Panggil Fungsi → Hapus → Hitung → Gambar → Minta dipanggil lagi
- (1/60 detik kemudian) Browser memanggil fungsi lagi
- Hapus → Hitung → Gambar → Minta dipanggil lagi
- Terus berulang secepat kedipan monitor (biasanya 60x sebdetik).
💻 Kode (state-based.js)
function stateFrame() {
  // Jika game sedang tidak di-pause
  if (!statePaused) {
    stateClear();   // Langkah 1: Hapus layar
    stateUpdate();  // Langkah 2: Hitung posisi baru
    stateDraw();    // Langkah 3: Gambar ulang
    
    // Catat sudah berapa kali layar digambar
    stateFrames++;
  }
  
  // Trik: Minta browser memanggil fungsi ini lagi 
  // di frame berikutnya! (Siklus tak berujung)
  requestAnimationFrame(stateFrame);
}

// Pemicu pertama kali untuk menghidupkan mesin
requestAnimationFrame(stateFrame);
💡 Kecerdasan requestAnimationFrame adalah: jika kamu pindah ke tab YouTube atau tab web lain, mesin ini akan otomatis berhenti sementara (pause). Ini menghemat daya baterai laptop sangat besar dibanding menggunakan setInterval model lama!

GERAKAN FISIKA
Menggerakkan Bola dengan Kecepatan (Velocity)
Untuk membuat benda bergerak, benda itu harus punya Kecepatan (Velocity). Kecepatan ini ibarat "bensin" yang ditambahkan ke posisinya setiap kali layar menggambar ulang.
📋 Penjelasan Logika & Pseudocode
// MEMBERIKAN BENSIN (KECEPATAN) KE BOLA
Bola butuh dua jenis bensin:
- Kecepatan Mendatar (vx) : untuk maju/mundur (Kiri-Kanan)
- Kecepatan Menurun (vy)  : untuk naik/turun (Atas-Bawah)

Nilainya menentukan arah:
+ (Positif) = Bergerak ke Kanan / Bawah
- (Negatif) = Bergerak ke Kiri / Atas

// BAGAIMANA BOLA BISA MAJU?
Di setiap frame (1/60 detik), kita lakukan matematika sederhana:
1. Posisi X Bola = Posisi X Bola + Kecepatan vx
   (Contoh: Posisi awal 100, Kecepatan +3 → Sekarang jadi 103)
2. Posisi Y Bola = Posisi Y Bola + Kecepatan vy

Kalau langkah ini diulang 60 kali sebdetik, bola X yang awalnya di 100 
akan meluncur mulus sampai X=280! Mata kita melihatnya sebagai gerakan nyata.
💻 Kode (state-based.js — stateUpdate)
function stateUpdate() {
  // Tambahkan "bensin kecepatan" ke posisi X
  // Penulisan singkat dari: stateBall.x = stateBall.x + stateBall.vx
  stateBall.x += stateBall.vx;
  
  // Tambahkan "bensin kecepatan" ke posisi Y
  stateBall.y += stateBall.vy;

  // (Catatan: Kode untuk memantul ada di bagian Challenge!)
}
💡 Konsep menambahkan Kecepatan ke Posisi setiap frame ini adalah hukum fisika paling mendasar di setiap pembuatan video game di dunia. Semua game 2D maupun 3D memakai prinsip matematika yang sama persis seperti ini!

Tugas JavaScript adalah mendengarkan "Kejadian" (Event) yang dilakukan oleh manusia. Entah itu manusia menggeser mouse, menekan tombol keyboard, atau mengklik layar. JavaScript bertugas menangkap kejadian itu dan mengubahnya menjadi reaksi di layar.

METODE 1 (MULUS)
Keyboard State-Based — Rahasia Pergerakan Game Mulus
Pernah main game di mana karakternya jalan sangat mulus selama tombol ditahan? Itu karena gamenya menggunakan metode State-Based. Gamenya tidak menyuruh karakter gerak saat tombol ditekan, tapi game "Mengingat" tombol apa yang sedang ditahan, dan menggerakkan karakter terus menerus.
📋 Penjelasan Logika & Pseudocode
// LOGIKA BUKU CATATAN (STATE):
Kita siapkan sebuah buku catatan kosong.

Saat manusia menekan tombol "W" (Event keydown):
- Kita tulis di catatan: "Tombol W sedang DITAHAN"

Saat manusia melepas tombol "W" (Event keyup):
- Kita hapus catatannya: "Tombol W sudah DILEPAS"

// MESIN ANIMASI BERTINDAK:
Di dalam game loop (yang berjalan 60x sebdetik), 
mesin selalu mengecek buku catatan tersebut:
- "Halo buku, apakah tombol W sedang ditahan?"
- Jika IYA: "Oke, dorong karakter ke atas sedikit!"
- Karena mesin mengecek 60x sebdetik, karakter akan
  bergerak ke atas 60 langkah kecil setiap detiknya.
→ Hasilnya: Pergerakan yang super duper mulus tanpa macet!
💻 Kode (state-based.js)
// 1. Siapkan "Buku Catatan" (Object kosong)
const stateKeys = {};

// 2. Manusia Menekan Tombol → Catat!
window.addEventListener("keydown", e => {
  stateKeys[e.key] = true; // DITAHAN
});

// 3. Manusia Melepas Tombol → Hapus Catatan!
window.addEventListener("keyup", e => {
  stateKeys[e.key] = false; // DILEPAS
});

// 4. Mesin Animasi Bertindak (Dicek tiap frame)
function stateUpdatePlayer() {
  const s = 5; // Kecepatan dorong
  
  // Jika di buku tercatat "d" ditahan, dorong ke kanan!
  if (stateKeys.d) { statePlayer.x += s; }
  
  // Jika "a" ditahan, dorong ke kiri!
  if (stateKeys.a) { statePlayer.x -= s; }
}
💡 Metode ini memungkinkan kita berjalan serong (diagonal)! Kenapa? Karena saat kita menahan tombol Atas(W) dan Kanan(D) bersamaan, buku catatan akan mengingat keduanya 'true'. Mesin pun akan mendorong karakter ke atas DAN ke kanan di frame yang sama.

METODE 2 (PATAH)
Keyboard Event-Based — Cocok Untuk Ketikan & Menu
Metode Event-Based adalah kebalikan dari cara di atas. Karakter tidak digerakkan oleh mesin animasi, melainkan hanya bergerak pasca tombol dipencet. Karena keyboard komputer punya jeda (delay) saat tombol ditahan, gerakannya akan terasa macet di awal lalu patah-patah.
📋 Penjelasan Logika & Pseudocode
// LOGIKA REAKSI INSTAN:
Tidak ada buku catatan. Tidak menunggu mesin animasi.

SAAT tombol "W" ditekan:
- SECARA INSTAN, paksa karakter geser ke atas 5 langkah.
- Selesai. Tugas selesai.

// KENAPA GERAKANNYA PATAH-PATAH SAAT DITAHAN?
Ini karena sistem operasi komputer (Windows/Mac) punya sifat:
"Jika tombol ditahan, ketik satu huruf.. tunggu sejenak.. 
baru ketik huruf berulang-ulang."
(Coba tahan tombol W di Notepad, pasti w.....wwwww)

Akibatnya di layar:
Karakter gerak 1 kali... (diam menunggu jeda OS)... baru gerak cepat.
Ini tidak enak untuk game Action, tapi SANGAT COCOK untuk:
- Game Catur (Kursor gerak per kotak)
- Memilih Menu / Inventori
- Game turn-based RPG kuno
💻 Kode (event-based.js)
// Reaksi Instan saat tombol ditekan
window.addEventListener("keydown", e => {
  const k = e.key.toLowerCase();
  const s = 5; // jarak lompat

  // Langsung paksa ubah koordinat saat itu juga
  if (k === "d") eventPlayer.x += s;
  if (k === "a") eventPlayer.x -= s;
  if (k === "w") eventPlayer.y -= s;
  if (k === "s") eventPlayer.y += s;
  
  // Layar baru digambar ulang NANTI oleh game loop,
  // tapi angkanya sudah dipaksa berubah sekarang.
});
💡 Coba rasakan sendiri perbedaannya! Klik tombol "Event-Based" di panel atas, lalu tahan tombol D untuk bergerak ke kanan. Bandingkan rasanya dengan saat kamu menggunakan mode "State-Based".

TANTANGAN #1
Bola Biliar: Memantul di Dinding Layar
Bagaimana membuat bola tidak tembus menghilang keluar layar? Jawabannya sederhana: kita pasang "Penjaga Dinding" (Kondisi If). Jika penjaga melihat bola melewati garis pinggir, penjaga akan memaksa bola Berbalik Arah secara ekstrem!.
📋 Penjelasan Logika & Pseudocode
// LOGIKA PENJAGA DINDING KANAN-KIRI (SUMBU X)
Bola sedang melaju santai ke kanan (Kecepatan X = +3).

Penjaga mengecek:
"Apakah bagian kanan bola melewati lebar maksimal canvas?"
- Jika IYA: "Dilarang lewat! Putar balik sekarang!"
- Cara komputer memutar balik sangat jenius: 
  Kalikan kecepatan dengan -1!
  Kecepatan +3 dikali -1 = Menjadi -3 (Kecepatan ke Kiri!)
  
Bola pun sekarang bergerak mundur teratur.
Begitu dia menyentuh dinding kiri (0), kalikan -1 lagi!
-3 dikali -1 = +3 (Maju ke kanan lagi!). Terus memantul selamanya.

// PERHATIAN SOAL JARI-JARI (RADIUS)
Kita harus memperhitungkan pinggiran bolanya. 
Kalau kita cuma cek 'Titik Tengah' bolanya, 
setengah badan bola akan tembus layar sebelum dia sadar untuk memantul.
💻 Kode (state-based.js)
// Posisi bola + Jari-jari (r) = Tepi Kanan Bola
// SW = Lebar Canvas penuh

// PENJAGA DINDING KIRI & KANAN
if (stateBall.x < stateBall.r || 
    stateBall.x > SW - stateBall.r) {
  // Putar Balik Arah X!
  stateBall.vx = stateBall.vx * -1;
}

// PENJAGA DINDING ATAS & BAWAH
if (stateBall.y < stateBall.r || 
    stateBall.y > SH - stateBall.r) {
  // Putar Balik Arah Y!
  stateBall.vy = stateBall.vy * -1;
}
💡 Trik mengalikan dengan -1 adalah keajaiban matematika yang membuat pemrograman animasi sangat indah. Satu baris kode mampu menyelesaikan masalah rumit dari dua sisi dinding sekaligus (kiri dan kanan)!

TANTANGAN #2
Lingkaran Pelacak: Objek Mengikuti Mouse
Kita ingin ada bayangan lingkaran yang selalu menempel di ujung panah mouse. Caranya bukan dengan menggeser lingkarannya secara harfiah. Caranya adalah dengan selalu menggambar ulang lingkaran baru persis di mana mouse sedang berada saat itu.
📋 Penjelasan Logika & Pseudocode
// LOGIKA SATPAM PENYADAP
1. Pasang alat penyadap (Event Listener) di mouse manusia.
2. Tiap kali manusia menggeser mouse 1 milimeter pun,
   Alat penyadap diam-diam mencatat titik koordinat (X dan Y)-nya 
   ke dalam sebuah memori.

// LOGIKA PELUKIS CEPAT
3. Di dalam mesin animasi (yang melukis 60x sebdetik),
   Sang pelukis akan selalu melirik memori tersebut.
   "Oh, saat ini mouse di X=150, Y=300."
4. Pelukis menggambar lingkaran tepat di X=150, Y=300.
5. Seperenam puluh detik kemudian, mouse geser ke X=152.
   Pelukis menghapus layar, lalu menggambar lingkaran baru di X=152.

Hasilnya di mata manusia: Wah, lingkarannya hidup dan membuntuti mouse!
💻 Kode (state-based.js)
// MEMORI PENYIMPAN POSISI (SATPAM)
const stateMouse = { x: 0, y: 0 };

stateCanvas.addEventListener("mousemove", e => {
  // Trik menyelaraskan ukuran layar Windows dan Canvas
  const r = stateCanvas.getBoundingClientRect();
  
  // Simpan posisi mouse terbaru ke memori!
  stateMouse.x = (e.clientX-r.left)*SW/r.width;
  stateMouse.y = (e.clientY-r.top) *SH/r.height;
});

// TUGAS SANG PELUKIS (Dalam fungsi Draw tiap frame)
stateCtx.beginPath();
// Gambar lingkaran berpusat di memori mouse
stateCtx.arc(stateMouse.x, stateMouse.y, 18, 0, Math.PI * 2);
stateCtx.strokeStyle = "#22d3ee"; // Warna biru cyan neon
stateCtx.stroke();
💡 Hal yang sering bikin pusing pemula: kenapa harus dihitung pakai getBoundingClientRect()? Karena koordinat mouse dari Windows itu dihitung dari pojok layar komputermu, sedangkan kita butuh koordinat dari pojok kotak Canvas saja. Rumus ini adalah alat penerjemah bahasanya.

TANTANGAN #4
Penjara Tanpa Teralis: Fungsi "Clamp" (Jepit)
Kita sudah bisa menggerakkan kotak kuning (Player) dengan WASD. Tapi tunggu dulu, kotaknya bisa bablas keluar layar dan hilang ditelan kegelapan! Kita harus membuat "Penjara Tanpa Teralis" yang tidak membiarkan nilai posisi kotak melebihi batas layar. Teknik sakti ini bernama Clamp (Jepit).
📋 Penjelasan Logika & Pseudocode
// APA ITU CLAMP (JEPIT)?
Bayangkan alat penjepit nilai. Kita punya nilai X, dan kita bilang:
"Nilai X, kamu boleh membesar sesukamu, TAPI maksimal 900 ya.
 Dan kamu boleh mengecil, TAPI minimal harus 0."

Jika Kotak ngotot jalan terus ke kanan sampai nilai X = 950:
Alat Clamp berteriak: "Maksimal 900!"
Lalu alat itu dengan paksa memotong nilai X kembali menjadi 900.
Hasilnya: Kotak tertahan seolah membentur tembok transparan!

// RUMUS JEPIT DALAM JAVASCRIPT:
Jepit Minimal: Gunakan Math.max(BatasMin, Nilai)
→ "Pilih mana yang lebih besar, angka 0 atau nilaimu saat ini?"

Jepit Maksimal: Gunakan Math.min(BatasMax, Nilai)
→ "Pilih mana yang lebih kecil, angka Maksimal atau nilaimu saat ini?"
💻 Kode (state-based.js)
// Mesin Penjepit Ringkas (Fungsi Clamp)
// Digabung dalam satu baris maut!
const sclamp =
  (nilai, min, max) => Math.max(min, Math.min(max, nilai));

function stateUpdatePlayer() {
  // ... kode menggeser player WASD disini ...

  // HUKUM PENJARA: 
  // X tidak boleh kurang dari 0, dan 
  // tidak boleh lebih dari Lebar Layar dikurangi Lebar Kotaknya.
  statePlayer.x = sclamp(
    statePlayer.x, 0, SW - statePlayer.w
  );
  
  // Y tidak boleh kurang dari 0, dll.
  statePlayer.y = sclamp(
    statePlayer.y, 0, SH - statePlayer.h
  );
}
💡 Rumus Clamp adalah dewa penolong di semua video game. Fungsi ini digunakan untuk apa saja: membatasi batas nyawa (HP) agar tidak minus, membatasi kecepatan maksimal mobil balap, hingga mencegah karakter keluar dari peta (Map).
