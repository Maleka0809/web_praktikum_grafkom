SOAL PRAKTIKUM

Penjelasan Logika & Implementasi

Berikut adalah penjelasan teknis untuk setiap komponen praktikum Canvas API.

HTML Canvas

Canvas API menyediakan sarana untuk menggambar grafis secara dinamis via JavaScript. Area canvas ditentukan pada dokumen HTML, sedangkan proses rendering seluruhnya dikontrol melalui script.

1
KONSEP DASAR
Inisialisasi Canvas dan Konteks 2D
Rendering pada canvas membutuhkan elemen HTML dan inisialisasi context pada JavaScript. Konteks (context) ini menyediakan berbagai metode standar untuk manipulasi piksel dan grafis vektor 2D.

Penjelasan Logika

  • Tahap 1: Mendefinisikan elemen <canvas> di dalam struktur HTML dengan atribut width dan height untuk menentukan dimensi area render.
  • Tahap 2: Mendapatkan referensi DOM ke elemen canvas tersebut melalui fungsi document.getElementById().
  • Tahap 3: Menginisialisasi Rendering Context menggunakan getContext("2d"). Objek context ini merupakan antarmuka (API) utama untuk memanggil instruksi penggambaran.
  • Tahap 4: Melakukan eksekusi metode menggambar seperti fillRect() (untuk persegi) atau arc() (untuk lingkaran) menggunakan instance dari context tersebut.
Kode HTML + JavaScript (state-based.js)
<!-- Di file HTML: buat elemen canvas -->
<canvas
  id="graphicsCanvas"
  width=960
  height=600>
</canvas>

// Di JavaScript: ambil canvas dan konteks
const stateCanvas = document.getElementById("graphicsCanvas");
const stateCtx = stateCanvas.getContext("2d");

// Simpan dimensi dalam konstanta
const SW = stateCanvas.width;  // 960
const SH = stateCanvas.height; // 600
2
SISTEM KOORDINAT
Koordinat X dan Y pada Canvas
Sistem koordinat Canvas berbeda dengan sistem kartesian pada umumnya. Titik origin ditempatkan di sudut kiri atas elemen canvas.

Penjelasan Logika

  • Titik awal (0, 0) berada secara mutlak di sudut kiri atas.
  • Sumbu X bernilai positif ke arah kanan.
  • Sumbu Y bernilai positif ke arah bawah.
  • Untuk menentukan titik pusat (center point) dari canvas, digunakan perhitungan: koordinat X = lebar canvas / 2, dan Y = tinggi canvas / 2.
Kode — Contoh Posisi
// Mendapatkan dimensi
const SW = stateCanvas.width;
const SH = stateCanvas.height;

// Render persegi di titik origin (kiri atas)
ctx.fillRect(0, 0, 100, 50);

// Render persegi di tengah canvas
// Koordinat digeser sebesar setengah dimensi objek
ctx.fillRect(
  (SW / 2) - 50,  
  (SH / 2) - 25,  
  100, 50
);
3
URUTAN MENGGAMBAR
Mendefinisikan State sebelum Instruksi Render
Rendering pada Canvas berbasis state (State Machine). Atribut visual (seperti warna atau ketebalan) harus diatur ke dalam context terlebih dahulu sebelum pemanggilan metode instruksi perenderan.

Penjelasan Logika

  • Instruksi Langsung (Rect): Mengatur warna menggunakan fillStyle, dilanjutkan dengan metode fillRect() yang segera merender persegi pada kanvas.
  • Instruksi Berbasis Lintasan (Path): Bentuk kompleks memerlukan penentuan koordinat jalur secara matematis sebelum dirender:
    • beginPath(): Menginisialisasi jalur baru dan menghapus state lintasan memori sebelumnya.
    • moveTo(): Menggeser titik awal kursor ke koordinat tertentu tanpa menggambar garis.
    • lineTo(): Menambahkan segmen lintasan lurus dari posisi kursor saat ini ke koordinat tujuan.
    • stroke() / fill(): Menerapkan state visual (seperti strokeStyle) pada lintasan (path) yang telah didefinisikan ke memori piksel Canvas.
Kode — Perbandingan (state-based.js)
// Metode langsung (Instruksi fillRect)
stateCtx.fillStyle = "#3b82f6";
stateCtx.fillRect(80, 90, 170, 105);

// Metode lintasan (Instruksi Path)
stateCtx.beginPath();       // Memulai lintasan baru
stateCtx.moveTo(310, 110);  // Menetapkan titik awal
stateCtx.lineTo(500, 185);  // Menetapkan titik akhir segmen
stateCtx.strokeStyle = "#f43f5e"; // Mendefinisikan warna garis
stateCtx.lineWidth   = 4;         // Mendefinisikan ketebalan
stateCtx.stroke();          // Mengeksekusi render garis

Primitif

Bentuk primitif merupakan instruksi grafis dasar yang disediakan secara native oleh API Canvas. Kombinasi primitif geometris (segi empat, garis, busur) ini menyusun komposisi dari objek grafis kompleks.

4
BENTUK 1
Persegi (Rectangle)
Persegi adalah satu-satunya entitas bentuk (shape) pada API Canvas yang memiliki fungsi utilitas untuk merender instan tanpa menggunakan instruksi path.

Penjelasan Logika

  • Metode fillRect() memproses 4 argumen berurutan secara spesifik:
  • Argumen 1: Titik koordinat absis (X) dari kiri-atas persegi.
  • Argumen 2: Titik koordinat ordinat (Y) dari kiri-atas persegi.
  • Argumen 3: Besaran lebar (width) dari persegi ke arah kanan.
  • Argumen 4: Besaran tinggi (height) dari persegi ke arah bawah.
Kode (state-based.js)
stateCtx.fillStyle = "#3b82f6";
// Render blok padat: fillRect(X, Y, Width, Height)
stateCtx.fillRect(80, 90, 170, 105);

// Render kerangka tepi luar (outline)
stateCtx.strokeStyle = "#3b82f6";
stateCtx.lineWidth   = 2;
stateCtx.strokeRect(80, 90, 170, 105);
5
BENTUK 3
Lingkaran (Arc / Circle)
Objek lingkaran dihasilkan dengan menggunakan metode lintasan kurva atau busur (Arc). Instruksi ini memanfaatkan notasi ukuran sudut dalam satuan radian.

Penjelasan Logika

  • Pembuatan lingkaran diinisiasi dengan beginPath() dan menggunakan fungsi arc(x, y, radius, startAngle, endAngle).
  • Koordinat (x, y) menentukan letak origin (titik pusat) lingkaran, dan radius merepresentasikan jarak garis melengkung dari titik pusat tersebut.
  • Sistem rotasi Canvas API menggunakan perhitungan radian, di mana panjang keliling satu lingkaran ekuivalen dengan rumus Math.PI * 2.
  • Metode fill() diaplikasikan di akhir untuk mewarnai geometri tersebut menjadi lingkaran padat.
Kode (state-based.js)
stateCtx.beginPath();
// Parameter: X, Y, Radius, Sudut Awal, Sudut Akhir (2 * PI)
stateCtx.arc(
  700, 135,
  58,
  0, Math.PI * 2
);
stateCtx.fillStyle = "#22c55e";
stateCtx.fill();
6
BENTUK 4
Poligon Tertutup (Segitiga)
Pembentukan poligon seperti segitiga mengandalkan pemetaan tiga garis titik yang diakhiri dengan instruksi penyatuan path, yaitu closePath().

Penjelasan Logika

  • Tahapan pembuatan segitiga: inisiasi path baru, penentuan koordinat awal dengan moveTo(), dan memplot dua garis vertex selanjutnya dengan lineTo().
  • Fungsi closePath() mengeksekusi instruksi pembentukan segmen lurus otomatis dari vertex terakhir kembali ke origin (koordinat moveTo), menciptakan poligon tertutup yang dapat diisi warna.
Kode (event-based.js)
stateCtx.beginPath();
stateCtx.moveTo(130, 360); // Titik puncak (Vertex atas)
stateCtx.lineTo(65,  490); // Verteks kiri bawah
stateCtx.lineTo(195, 490); // Verteks kanan bawah

// Menyambungkan titik akhir secara otomatis ke puncak
stateCtx.closePath();

stateCtx.fillStyle = "#f97316";
stateCtx.fill();

Warna & Efek Visual

7
TRANSPARANSI
Manipulasi Nilai Alpha Channel (RGBA)
Nilai transparansi dari objek diatur melalui kanal Alpha pada model warna RGBA. Teknik ini secara khusus dapat dieksploitasi untuk menghasilkan motion blur atau trail effect dalam sistem frame loop.

Penjelasan Logika

  • Nilai float untuk Alpha channel beroperasi pada batasan 0.0 (fully transparent) sampai 1.0 (fully opaque).
  • Mekanisme Trail Animasi: Dalam setiap perulangan siklus render (frame refresh), kanvas tidak dihapus secara menyeluruh dengan metode clearRect, melainkan dilapisi oleh persegi (fillRect) sebesar ukuran layar.
  • Persegi tersebut menggunakan format fill warna latar (misal: hitam) dengan nilai Alpha rendah (contoh: 0.13). Redudansi lapisan semi-transparan ini pada piksel bola lama mengakibatkan pengikisan warna bertahap yang menciptakan jejak (trail) berkesinambungan.
Kode (state-based.js)
// Pendefinisian warna dengan Alpha sebesar 13%
// rgb(merah, hijau, biru), alpha(transparansi)
stateCtx.fillStyle = "rgba(7, 17, 31, 0.13)";

// Lapisan kotak semi-transparan di seluruh layar
stateCtx.fillRect(0, 0, SW, SH);
8
ROTASI STATE
Pengindeksan dengan Operator Modulo (%)
Pergantian status komponen secara melingkar (siklik) dapat ditangani menggunakan perpaduan variabel indeks dan operator aritmetika Modulo, tanpa harus bergantung pada kondisional logika if-else yang panjang.

Penjelasan Logika

  • Variabel warna dideklarasikan dalam tipe data kumpulan (Array) dan indeks status ditugaskan dengan nilai 0.
  • Pada saat callback event dieksekusi (contoh: 'click'), nilai state index diperbarui dengan persamaan matematis: (indexSaatIni + 1) % elemenTotalArray.
  • Fungsi modulus mengembalikan sisa hasil bagi, memastikan nilai indeks mengulang ke angka 0 saat mencapai ekuivalensi iterasi dari panjang elemen maksimal array. Array index error (out of bounds) dapat dihindari secara konstan.
Kode (state-based.js)
// Array data set heksadesimal warna
const stateColors = ["#8b5cf6", "#f43f5e", "#22c55e", "#3b82f6"];
let stateColorIndex = 0; 

stateCanvas.addEventListener("click", () => {
  // Pembaruan index melalui fungsi matematika modulo
  stateColorIndex = (stateColorIndex + 1) % stateColors.length;
  stateBall.color = stateColors[stateColorIndex];
});
9
SHADOW
Implementasi Glow Effect via Atribut Shadow
Tidak ada native API untuk efek Neon Glow pada HTML5 Canvas. Implementasinya memanfaatkan render properti bayangan (Shadow) dengan parameter blur yang dilebarkan secara konstan sebanding dengan objek bersangkutan.

Penjelasan Logika

  • Pendaran warna dikonfigurasi melalui penetapan shadowColor (yang umumnya mengambil variable color yang sama dengan instance primitif yang dirender).
  • Intensitas dispersi efek dicapai dengan meningkatkan skala nilai properti shadowBlur.
  • Aturan Sinkronisasi State: Karena konteks 2D akan mempertahankan instruksi styling untuk draw call selanjutnya, properti blur wajib di-reset (dinolkan) segera pasca pemanggilan render fill() atau stroke() objek yang dituju.
Kode (state-based.js)
stateCtx.beginPath();
stateCtx.arc(stateBall.x, stateBall.y, stateBall.r, 0, Math.PI * 2);
stateCtx.fillStyle = stateBall.color;

// Aplikasi state bayangan (Glow simulation)
stateCtx.shadowBlur  = 25;          
stateCtx.shadowColor = stateBall.color; 

stateCtx.fill(); // Render target dengan glow layer

// Penetralan state memori (Mencegah perambatan glow)
stateCtx.shadowBlur  = 0;

Animasi (Game Loop)

10
RENDER LOOP
Sinkronisasi Frame (requestAnimationFrame)
Metode standar Web API untuk mengeksekusi operasi animasi yang efisien pada DOM Canvas adalah requestAnimationFrame(), sebagai substitusi superior atas metode timeout tradisional.

Penjelasan Logika

  • Pola arsitektur standar loop rendering dieksekusi secara iteratif melalui tiga tahapan berurutan: metode pembersihan latar canvas (Clear), perhitungan matematis posisi vektor koordinat entitas grafis (Update), dan penggambaran pergeseran posisi grafis terakhir ke layer memori Canvas (Draw).
  • Di penutup deklarasi blok fungsi tersebut, dieksekusi pemanggilan fungsi eksternal requestAnimationFrame(fungsiLoopSendiri). Hal ini menciptakan perulangan rekursif asinkron dengan perantara browser.
  • Browser akan mengendalikan jadwal fungsi ini, mensinkronisasikannya dengan waktu repaint layar display yang aktif, yang berdampak positif pada efisiensi thread prosesor apabila proses tab jendela tidak aktif (suspend rendering mode).
Kode (state-based.js)
function stateFrame() {
  if (!statePaused) {
    stateClear();   // Modul Pembersihan
    stateUpdate();  // Modul Komputasi Vektor Update
    stateDraw();    // Modul Implementasi Rendering Visual
  }
  
  // Asynchronous recursive call untuk penjadwalan frame berikutnya
  requestAnimationFrame(stateFrame);
}

// Pemanggilan instansiasi proses loop pertama kali 
requestAnimationFrame(stateFrame);
11
VEKTOR KOORDINAT
Komputasi Translasi (Kecepatan Vektor)
Entitas yang dianimasikan dioperasikan menggunakan prinsip kinematika yang mendefinisikan perubahan posisi (displacement) yang diamplifikasi oleh besaran kecepatan dalam iterasi waktu (loop).

Penjelasan Logika

  • Vektor entitas mencakup variabel translasi horizontal atau velocity sumbu x (vx), dan vektor translasi vertikal atau velocity sumbu y (vy).
  • Di dalam loop update(), skalar numerik pada koordinat X entitas dievaluasi dengan menyeimbangkan atau mengakumulasi titik awal dengan variabel vx tersebut (demikian pula hal yang direplikasikan pada sumbu Y).
  • Komputasi penjumlahan berkelanjutan (frame demi frame) akan menghasilkan translasi kontinu objek yang secara konseptual dapat diamati secara visual sebagai fenomena pergerakan.
Kode (state-based.js)
function stateUpdate() {
  // Akumulasi posisi X dengan velocity X secara iteratif
  // Ekuivalen dengan operasi: stateBall.x = stateBall.x + stateBall.vx
  stateBall.x += stateBall.vx;
  
  // Akumulasi posisi Y dengan velocity Y secara iteratif
  stateBall.y += stateBall.vy;
}

Interaksi & Event

12
SISTEM KENDALI MULUS
Implementasi Mekanisme State-Based Keyboard
Metode state-based dirancang untuk mengantisipasi penundaan repetisi bawaan pada input keyboard hardware, yang penting untuk memastikan pembaruan lintasan koordinat yang mulus secara terus-menerus pada sistem interaktif (mis. game loop).

Penjelasan Logika

  • Sebuah obyek penampung data lokal digunakan untuk memelihara state presensi status per setiap tuts (key mapping).
  • Pendengar input (event listener) memantau keydown untuk menetapkan properti pemetaan boolean key string di dalam state obj tersebut menjadi true, dan keyup membalik state valuenya ke kondisi false.
  • Perubahan state translasi pada subjek/entitas hanya dipantau langsung dalam update event (frame renderer). Jika boolean mengembalikan komparasi validasi nilai aktual (true), fungsi interpolasi sumbu koordinat dijalankan dengan proporsi besaran pergeseran yang konsisten per rendering iteration.
  • Hal ini memfasilitasi rendering diagonal yang responsif bila dua key state string dievaluasi `true` secara konkuren di satu iterasi render frame yang sama.
Kode (state-based.js)
// 1. Deklarasi object state penampung keyboard mapping
const stateKeys = {};

// 2. Konfigurasi peremajaan State pada DOM input Listener
window.addEventListener("keydown", e => { stateKeys[e.key] = true; });
window.addEventListener("keyup",   e => { stateKeys[e.key] = false; });

// 3. Integrasi implementasi validasi aksi pada metode iteratif Loop
function stateUpdatePlayer() {
  const s = 5; // Skalar translasi absolut per iterasi pergerakan frame
  
  // Validasi keymap identifier 'd' (Translasi Right vector positif)
  if (stateKeys.d) { statePlayer.x += s; }
  
  // Validasi keymap identifier 'a' (Translasi Left vector negatif)
  if (stateKeys.a) { statePlayer.x -= s; }
}
13
SISTEM KENDALI DISKRET
Implementasi Mekanisme Event-Based Keyboard
Metode event-based, yang mengeksekusi rekayasa titik pembaruan sumbu (Update vector) sesegera setelah pemicu sinkronisasi API terjadi (tanpa iterasi terpisah pada rendering update frame-loop terpusat), cenderung sesuai diaplikasikan untuk perancangan instrumen UI seperti navigasi komponen panel dan menu sel diskret.

Penjelasan Logika

  • Eksekusi parameter keydown mengintervensi atau menambahkan nilai skalar pada subyek posisi variabel instan secara seketika.
  • Sistem interupsi register OS secara empiris menangguhkan interval impuls ke key handler (key-repeat rate behavior delay), yang menerjemahkan perilaku manipulasi layar berulang sehingga menimbulkan segmentasi gerakan awal subjek patah (stutter initial update motion), sebelum loop event input hardware stabil berjalan berurutan.
Kode (event-based.js)
// Modul modifikasi yang terpanggil seketika pada key invocation state
window.addEventListener("keydown", e => {
  const k = e.key.toLowerCase();
  const s = 5; // Skalar translasi modifikasi konstan

  // Konversi mutasi skalar atribut axis divalidasi langsung pada listener
  if (k === "d") eventPlayer.x += s;
  if (k === "a") eventPlayer.x -= s;
  if (k === "w") eventPlayer.y -= s;
  if (k === "s") eventPlayer.y += s;
});

Tantangan (Implementasi Logika)

14
TANTANGAN #1
Collision Detection: Pantulan Objek di Batas Layar
Pembatasan wilayah pergerakan memerlukan metode deteksi tabrakan (Boundary Collision Detection) antara vektor geometri subjek yang dimutasi dengan parameter ujung skalar terluar dari ukuran ruang memori koordinat grid canvas (Width dan Height).

Penjelasan Logika

  • Metode deteksi batas tepi (X Boundary): Menyusun perbandingan nilai antara koordinat posisi subjek saat ini (diakumulasi dengan koefisien konstanta offset ukuran radiusnya) dan angka rasio ekstrem kanvas maksimum dan minimum wilayah 0.
  • Apabila perbandingan boolean pengujian kondisional mengembalikan komparator indikasi pelampauan sumbu ekstrim, modifikasi operasional perkalian -1 di-assign untuk diinversikan secara logis dari bilangan riil sumbu tersebut (Pembalikan Velocity Vector Positif menjadi Negatif, dan sebaliknya).
  • Komputasi radius disertakan saat menyusun validasi operasi grid agar pelampauan grafis elemen subjek sebelum frame eksekusi putar balik sepenuhnya terjadi (memantulkan objek pas menyentuh sisi tepinya).
Kode (state-based.js)
// Validasi Collision Horizontal (X Axis Constraint Mapping)
// Pengecekan limit minimal tepi Kiri dan limit maksimal tepi Kanan
if (stateBall.x < stateBall.r || stateBall.x > SW - stateBall.r) {
  // Reverse Polarity operasi Velocity vektor
  stateBall.vx = stateBall.vx * -1;
}

// Validasi Collision Vertikal (Y Axis Constraint Mapping)
// Pengecekan limit minimal batas Atas dan limit maksimal batas Bawah
if (stateBall.y < stateBall.r || stateBall.y > SH - stateBall.r) {
  // Reverse Polarity operasi Velocity vektor
  stateBall.vy = stateBall.vy * -1;
}
15
TANTANGAN #2
Event Coordinate Listener: Objek Mengikuti Mouse
Penyelarasan rendering geometris secara terus-menerus ke node kursor yang diinputkan dari user client diatur melalui transkripsi referensi event property (Mouse Coordinate Data Collection) pada sistem rendering per frame.

Penjelasan Logika

  • Event dispatcher mousemove dimonitor di DOM listener node root kanvas dan menangkap nilai clientX serta clientY di global context.
  • Algoritme mutlak translasi (Translation Constraint Mapper) dengan getBoundingClientRect() diperlukan karena client koordinat diwarisi oleh letak pixel posisi dari frame browser global viewport, sedangkan origin 0 canvas diletakkan secara relatif menurut penempatan orientasi style di parent document flow.
  • Pembaruan nilai kalkulasi dikonfigurasi dan diikat menjadi referensi ke satu var state statik yang dibaca dari modul prosedur Loop animasi rendering utama.
Kode (state-based.js)
// Modul state deklaratif untuk parameter letak buffer listener
const stateMouse = { x: 0, y: 0 };

stateCanvas.addEventListener("mousemove", e => {
  // Pengambilan orientasi matrix rendering ukuran absolut root di Viewport
  const r = stateCanvas.getBoundingClientRect();
  
  // Matematika normalisasi data global viewport ke Local Coordinate frame
  stateMouse.x = (e.clientX - r.left) * SW / r.width;
  stateMouse.y = (e.clientY - r.top) * SH / r.height;
});

// Konstruksi ulang instance visual arc yang diposisikan di vektor baru ini 
// Diambil secara asinkron dari metode frame Draw
stateCtx.beginPath();
stateCtx.arc(stateMouse.x, stateMouse.y, 18, 0, Math.PI * 2);
stateCtx.strokeStyle = "#22d3ee";
stateCtx.stroke();
16
TANTANGAN #4
Constraint Logic: Matematika Fungsi Clamp
Subjek Player (kotak yang dapat dikontrol bebas) memerlukan metode logikal mitigasi batas margin (Boundary Logic Restrict Constraint), yang dikenal sebagai fungsi "Clamp", untuk menghindari subjek teranotasi koordinat menyeberang ruang kosong (Out of bounds) render window.

Penjelasan Logika

  • Algoritma penjepitan batas (Clamp Function) menerima argumen utama komputasional: Nilai aktual sumber subjek, skala ekstrem batas minimum operasi, dan skala ekstrem batas maksimum.
  • Evaluasi internal dari subrutin matematis menggunakan evaluasi statis yang dibungkus Math.min() dan Math.max():
  • Tahap penyaringan batas maksimum: Mengomparasikan variabel awal mana yang merupakan koefisien terkecil (Variabel aktual ATAU Titik batas maksimal yang valid), untuk mengabaikan nilai luapan yang telah melampaui toleransi maksimum yang disyaratkan.
  • Tahap penyaringan batas minimum: Math.max(Minimum, (Hasil Filter Sebelumnnya)) memaksa hasil kembali pada limit batas angka terkecil valid apabila evaluasi bernilai di bawah titik 0 layar operasional.
Kode (state-based.js)
// Definisi abstraksi logika operasional fungsi jepit matematis (Clamp function)
const sclamp = (nilai, min, max) => Math.max(min, Math.min(max, nilai));

function stateUpdatePlayer() {
  // ... operasi mutasi subjek posisi x dan y melalui keyboard state input ...

  // Transformasi penjepitan subjek axis X: Restriksi 0 dan dimensi frame-lebar
  statePlayer.x = sclamp(
    statePlayer.x, 
    0, 
    SW - statePlayer.w
  );
  
  // Transformasi penjepitan subjek axis Y: Restriksi 0 dan dimensi frame-tinggi
  statePlayer.y = sclamp(
    statePlayer.y, 
    0, 
    SH - statePlayer.h
  );
}
