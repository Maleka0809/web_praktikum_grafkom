2. Blender Fundamental & Prinsip 3D Modeling Modeling Core Concepts

A. Ruang Cartesian 3D & Mode Kerja Blender

Blender beroperasi pada sistem koordinat Right-Handed Cartesian 3D dengan orientasi sumbu: Sumbu X (Merah, Kiri/Kanan), Sumbu Y (Hijau, Depan/Belakang), dan Sumbu Z (Biru, Atas/Bawah). Dalam alur kerja pemodelan, pengguna berpindah antara dua mode utama melalui tombol Tab:

  • Object Mode: Objek diperlakukan sebagai satu kesatuan utuh. Digunakan untuk manipulasi global (posisi dunia, rotasi keseluruhan, skala, duplikasi, dan manajemen modifier).
  • Edit Mode: Memberikan akses langsung ke komponen mikroskopis geometri penyusun mesh: Vertex (titik sudut 3D), Edge (garis penghubung dua vertex), dan Face (bidang poligon tertutup yang dibentuk oleh minimal 3 edge).

B. Transformasi Mesh Esensial & Hotkeys Standar di Blender

G (Grab / Move) Mentranslasikan vertex/edge/face terpilih. Tekan sumbu (X/Y/Z) untuk mengunci gerakan.
R (Rotate) Memutar komponen geometri relatif terhadap titik pivot (Median Point, 3D Cursor, Individual Origins).
S (Scale) Menskalakan ukuran geometri lebih besar atau lebih ramping ke arah sumbu tertentu.
E (Extrude) Mengekstrak geometri baru ke luar sepanjang vektor normal permukaan, membentuk volume baru.
I (Inset Faces) Membuat face baru di dalam perimeter face terpilih dengan batas edge loop yang rapi untuk hard-surface.
Ctrl + B (Bevel) Menumpulkan tepi tajam menjadi chamfer/fillet lengkung, krusial untuk menangkap highlight spekular cahaya.
Ctrl + R (Loop Cut) Menyisipkan cincin edge melingkar (edge loop) secara merata untuk menambah kerapatan segmen.
K (Knife Tool) Memotong poligon secara bebas untuk membuat topologi kustom tanpa terikat edge loop otomatis.

C. Topologi Mesh: Quads, Triangles, dan N-Gons

Kualitas sebuah model 3D ditentukan oleh topologinya:

  • Quad (4-sided polygon): Merupakan standar baku saat memodelkan di Blender. Quad memungkinkan algoritma Catmull-Clark Subdivision Surface menghasilkan kurvatur yang halus tanpa artefak bayangan.
  • Triangle / Tris (3-sided polygon): Poligon paling mendasar yang selalu planar (selalu rata). Seluruh GPU dan kartu grafis pada akhirnya hanya dapat merender segitiga.
  • N-Gon (> 4 sides): Face dengan lima sisi atau lebih. Sangat dihindari pada permukaan yang mengalami deformasi karena menyebabkan artefak bayangan (*pinching*).

D. Normal Shading: Flat Shading vs Smooth Shading

Persepsi kehalusan permukaan pada grafika komputer dikontrol oleh Vektor Normal Permukaan ($\vec{N}$):

  • Shade Flat: Vektor normal dihitung seragam per bidang poligon (Face Normal). Setiap segitiga memantulkan cahaya ke arah yang sama, menghasilkan tampilan berpola faset (*faceted/low-poly look*).
  • Shade Smooth: Vektor normal dihitung pada setiap vertex (Vertex Normal) dengan merata-ratakan normal dari semua face yang bertetangga. Diinterpolasi via Phong Normal Interpolation di Fragment Shader.

3. Arsitektur Shading & Principled BSDF di Blender PBR Shading Model

Blender mengadopsi standar Physically Based Rendering (PBR) melalui shader inti Principled BSDF (berbasis Disney BRDF). Prinsip utama PBR adalah menjaga hukum kekekalan energi (*Energy Conservation Law*), di mana jumlah total foton cahaya yang dipantulkan tidak boleh melebihi jumlah cahaya yang datang.

Parameter Kunci PBR Principled BSDF:

// Parameter Konfigurasi Standar PBR Principled BSDF
Base Color (Albedo) : Warna pantulan difus murni tanpa pengaruh pencahayaan bayangan.
Subsurface          : Penetrasi cahaya ke dalam material semi-transparan (kulit, lilin).
Metallic            : 0.0 (Dielektrik/Non-logam seperti plastik, kayu) s/d 1.0 (Konduktor/Logam).
Roughness           : Tingkat kekasaran mikroskopis permukaan (0.0 = cermin jernih, 1.0 = matte/kapur).
IOR (Index of Refraction) : Indeks bias optik Snellius (kaca = 1.52, air = 1.33).
Transmission        : Transparansi refraksi kaca (0.0 = solid, 1.0 = tembus pandang).
Emission            : Nilai pendaran cahaya mandiri (glow/neon effect).

Sistem Multi-Material Slot pada Objek Tunggal

Di Blender, sebuah objek mesh tidak terbatas pada satu material tunggal. Pengguna dapat membuat beberapa slot material pada tab Material Properties, memilih poligon tertentu di Edit Mode, lalu menekan tombol Assign. Pada aset grafkom1, teknik ini diterapkan sehingga bodi utama mendapatkan material navy, sasis mendapatkan material gelap, dan aksen mendapatkan material cyan pada mesh yang sama.

4. Pipeline Konversi: Dari Master .blend ke Runtime Web .glb Asset Pipeline & glTF Standard

Mengapa file master grafkom1.blend tidak dapat dimuat langsung di browser oleh Three.js/WebGL?

A. Mengapa File .blend Bersifat Desktop-Centric:

  • Format .blend adalah dump memori internal struktur data C/C++ Blender (struktur DNA1). File ini menyimpan informasi antarmuka (window layout), riwayat undo, pohon dependensi animasi, cache simulasi fisika, dan formula modifier yang belum di-bake.
  • Mengurai format .blend di JavaScript membutuhkan mesin Blender lengkap yang berukuran ratusan megabita, tidak efisien untuk transmisi web instan.

B. Keunggulan Format glTF / GLB (GL Transmission Format):

Khronos Group merancang glTF 2.0 sebagai "JPEG untuk Grafika 3D". Format binary .glb menyatukan struktur data menjadi berkas tunggal yang sangat efisien:

  1. Header 12-byte: Mengidentifikasi magic number 0x46546C67 (ASCII "glTF"), versi format (2), dan panjang total berkas.
  2. JSON Chunk (Structured Metadata): Menjelaskan hierarki node, deskripsi material PBR, kamera, animasi, serta accessor dan buffer view.
  3. Binary Buffer Chunk (RAW GPU Memory): Berisi koordinat posisi (VEC3 FLOAT), normal (VEC3 FLOAT), koordinat tekstur UV (VEC2 FLOAT), dan indeks segitiga (SCALAR USHORT/UINT) yang dapat langsung di-upload ke VRAM GPU melalui perintah WebGL gl.bufferData() tanpa pemrosesan parsing teks lambat.

C. Transformasi Sistem Koordinat: Blender (Z-Up) ke WebGL (Y-Up)

Blender menggunakan sistem koordinat tangan kanan dengan sumbu Z mengarah ke atas (Z-Up), sedangkan WebGL, OpenGL, dan Three.js menggunakan standar sumbu Y mengarah ke atas (Y-Up) dengan -Z mengarah ke kedalaman layar. Saat proses ekspor glTF berlangsung di Blender, eksportir secara otomatis mengalikan posisi dan normal dengan matriks rotasi $-90^\circ$ di sekitar sumbu X: 

[ X_webgl ]   [  1    0    0  ]   [ X_blender ]
[ Y_webgl ] = [  0    0    1  ] × [ Y_blender ]
[ Z_webgl ]   [  0   -1    0  ]   [ Z_blender ]

5. Tanya Jawab & Pertanyaan Analisis Komprehensif (A s/d H) Kajian Mendalam Grafika Komputer 3D

A — Box Modeling: Mengapa pemodelan 3D di Blender hampir selalu diawali dari "Default Cube" ketimbang menyusun vertex satu demi satu?
Jawab: Karena prinsip Topology Preservation, Efisiensi Volume Spasial, dan Konsistensi Manifold 3D.

Menyusun titik vertex secara manual (*point-by-point modeling*) sangat rawan menghasilkan geometri non-manifold (seperti lubang yang tidak tertutup, tepi terbuka, atau normal face yang terbalik arah). Kubus bawaan (Default Cube) sudah merupakan bentuk solid 3D tertutup sempurna (*watertight volume*) dengan 8 vertex, 12 edge, dan 6 face quad yang normalnya mengarah ke luar secara konsisten. Dengan teknik Box Modeling melalui kombinasi Extrude (E), Loop Cut (Ctrl+R), dan Scale (S), topologi quad tertutup tetap terjaga secara alami sepanjang proses sculpting volume tanpa risiko kebocoran geometri.
B — Format Pipeline: Apa perbedaan mendasar antara file master .blend dan file runtime .glb?
Jawab: Perbedaan terletak pada Peran Siklus Hidup Aset: Authoring Format vs Runtime Transmission Format.

  • File .blend (Authoring): Menyimpan data non-destruktif: stack modifier aktif (Subdivision, Mirror, Bevel) yang masih dapat disunting parameternya kapan saja, node tree procedural shader kompleks, struktur relasi armature animasi, hingga riwayat undo. File ini berorientasi pada kemudahan modifikasi oleh 3D artist di aplikasi desktop.
  • File .glb (Runtime): Format biner terkompresi Khronos glTF yang dirancang untuk transfer jaringan web cepat dan konsumsi langsung oleh GPU. Seluruh modifier telah di-*bake* (diaplikasikan permanen), face dipecah menjadi segitiga terindeks, dan shader dipetakan ke standar PBR standar industri. File ini berorientasi pada kecepatan rendering dan efisiensi memori runtime di browser.
C — Multi-Material Mechanism: Bagaimana cara kerja Multi-Material pada single mesh di Blender dan implementasinya di glTF/Three.js?
Jawab: Melalui pembagian poligon ke dalam Sub-Mesh Primitives yang memiliki material index berbeda.

Dalam struktur glTF 2.0, sebuah node mesh (seperti Cube pada grafkom1.glb) dapat memiliki array primitives. Setiap primitive menyimpan indeks buffer vertex dan indeks segitiganya sendiri, serta mereferensikan satu indeks material spesifik. Saat THREE.GLTFLoader membaca file ini di WebGL:
  • Jika primitive diekspor sebagai sub-bagian terpisah, Three.js memetakannya menjadi beberapa objek THREE.Mesh di dalam satu grup, masing-masing dengan THREE.MeshStandardMaterial mandiri.
  • Atau, Three.js menggunakan satu BufferGeometry dengan properti geometry.groups (Material Groups), di mana rentang indeks segitiga tertentu di-assign ke elemen array material yang sesuai (material[0], material[1], dst.).
Hal ini memungkinkan GPU merender bodi mobil dan kaca depan dari satu aset dengan draw call terorganisir.
D — Quads vs Tris: Mengapa Quads dipertahankan saat modeling di Blender, tetapi diwajibkan menjadi Segitiga (Tris) saat diekspor ke glTF/WebGL?
Jawab: Karena perbedaan kebutuhan antara Ergonomi Pemodelan Artistik dan Arsitektur Hardware Rasterizer GPU.

  • Untuk Artist (Blender): Quads (segi empat) memiliki dua pasang sisi sejajar yang memungkinkan algoritma mendeteksi arah aliran garis (Edge Flow). Hal ini membuat fungsi Loop Cut dapat membelah cincin geometri secara presisi dan membuat algoritma Subdivision Surface menghitung pembagian permukaan lengkung tanpa melintir (*pinching*).
  • Untuk GPU (WebGL): Tiga titik vertex selalu membentuk satu bidang datar sempurna (planar). Empat titik vertex (quad) di ruang 3D belum tentu datar (bisa melengkung/non-planar). Jika GPU mencoba merasterisasi poligon dengan >3 vertex yang tidak planar, perhitungan barycentric coordinate dan interpolasi kedalaman Z-buffer menjadi tidak pasti (*ambiguous*). Oleh sebab itu, tahap rasterizer GPU hanya menerima segitiga primitif (GL_TRIANGLES). Blender secara otomatis mentriangulasi setiap quad menjadi dua segitiga saat mengekspor ke glTF.
E — Coordinate Space Transformation: Mengapa sumbu Z di Blender mengarah ke atas, sedangkan di WebGL sumbu Y yang mengarah ke atas?
Jawab: Karena perbedaan warisan historis tradisi Architectural/Engineering (CAD) vs Computer Graphics / Screen Projection.

  • Blender (Z-Up): Mengikuti tradisi software CAD, arsitektur, dan manufaktur mesin, di mana kertas denah/tanah berada pada bidang 2D datar $(X, Y)$ di lantai, dan ketinggian struktur menjulang ke atas pada sumbu $Z$.
  • WebGL & OpenGL (Y-Up): Mengikuti tradisi layar monitor 2D awal grafika komputer, di mana bidang layar adalah $(X, Y)$ dengan sumbu $Y$ mengarah ke atas layar, dan sumbu $Z$ mewakili kedalaman (*depth*) menembus ke dalam atau ke luar layar.
Konversi diselesaikan dengan mengalikan matriks transformasi rotasi $-90^\circ$ pada sumbu X saat ekspor, memetakan $(X, Y, Z)_{blender} \mapsto (X, Z, -Y)_{webgl}$.
F — Principled BSDF & glTF PBR: Bagaimana pemetaan parameter shader dari Blender ke glTF PBR Metallic-Roughness?
Jawab: Menggunakan spesifikasi universal Khronos PBR Metallic-Roughness Model.

Format glTF 2.0 secara resmi menstandardisasi alur kerja Metallic-Roughness:
  • Base Color pada Principled BSDF disimpan sebagai baseColorFactor (vektor 4D RGBA) atau baseColorTexture.
  • Roughness disimpan sebagai roughnessFactor (kanal Hijau/G pada tekstur packed).
  • Metallic disimpan sebagai metallicFactor (kanal Biru/B pada tekstur packed).
  • Emission disimpan sebagai emissiveFactor (vektor 3D RGB).
Karena Three.js mengimplementasikan THREE.MeshStandardMaterial yang sepenuhnya mematuhi standar Cook-Torrance BRDF dan glTF 2.0, tampilan pantulan cahaya, kekasaran material, dan pendaran warna di browser tampak identik dengan apa yang dilihat artist di viewport EEVEE Blender.
G — Polycount Budget: Mengapa aset grafkom1 dengan 1.449 segitiga sangat ideal untuk grafika web interaktif?
Jawab: Karena mematuhi batasan Polycount Budget dan meminimalkan beban Vertex Processing & Memory Bandwidth.

Pada grafika web interaktif, target performa adalah mempertahankan refresh rate konstan 60 Frame Per Second (16,6 milidetik per frame):
  • Jumlah 1.449 segitiga dan 2.577 vertex dapat diproses oleh Vertex Shader GPU modern dalam waktu kurang dari 0,1 milidetik.
  • Ukuran berkas 95,1 KB dapat diunduh melalui koneksi seluler dalam hitungan milidetik, tidak membebani kuota pengguna dan memungkinkan waktu muat (*first contentful paint*) seketika.
  • Jumlah draw call rendah (hanya 4 primitive batch) meminimalkan overhead komunikasi antara CPU JavaScript dan GPU WebGL (*CPU-GPU context switching*).
H — ArrayBuffer Parsing di Three.js: Bagaimana GLTFLoader membaca data biner GLB dan menyusun Scene Graph?
Jawab: Melalui parsing terstruktur dari header biner ke TypedArray JavaScript dan Three.js BufferGeometry.

Tahapan yang dilakukan GLTFLoader saat memuat grafkom1.glb:
  1. Membaca 12 byte pertama untuk memvalidasi magic header glTF dan panjang total.
  2. Mengekstrak JSON chunk pertama dan mem-parsingnya menjadi objek JavaScript via JSON.parse().
  3. Mengekstrak binary chunk kedua menjadi satu objek ArrayBuffer tunggal di memori browser.
  4. Berdasarkan deklarasi bufferViews dan accessors di JSON, loader membuat tampilan Float32Array untuk posisi dan normal, serta Uint16Array untuk indeks segitiga tanpa perlu menyalin ulang memori.
  5. Instansiasi objek THREE.BufferGeometry dan pasang atribut melalui geo.setAttribute('position', new THREE.BufferAttribute(...)).
  6. Instansiasi THREE.MeshStandardMaterial dengan properti albedo, roughness, dan metalness yang diekstrak dari deskriptor material.
  7. Membungkus mesh ke dalam node hierarki THREE.Group dan mengembalikan gltf.scene yang siap ditambahkan langsung ke scene.add().
